## Acceptance criteria
- [x] Tests use a synthetic source behind a trait: `MockSource: AudioSource`, with streaming
  chunks, overflow, error injection and guard-release observation.
- [x] A manual capture on the reference OS is recorded: `docs/benchmarks/p4-capture.md`.

## Known limitations
- Other native platforms untested. Standard rates 8–192 kHz, 1–32 channels supported.
- The first native backend error was not reproduced or assigned a cause; no auto-retry added.
- The future runtime must keep one session, obey mute/cleanup, show capture state, drain the
  queue and bound full-utterance storage. CPAL internally owns the hardware callback thread.
- Queue overflow is counted; dropped audio is not reconstructed. Native guard release was
  exercised, but the OS microphone indicator was not independently observed.

## Security implications
- No filesystem persistence, uploads, cloud fallback or secret handling. Microphone access is
  explicit and subject to normal OS permissions. Errors close capture; Drop discards queued audio.
- Transcript-based approval is not implemented; SEC-11 remains an integration gate.
