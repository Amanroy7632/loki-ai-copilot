## Changed files
- `apps/desktop/src/approval/ApprovalDialog.tsx`: the dialog. Tool, plain-language risk, every argument as JSON with invisible and bidi-control characters shown as `\u{…}`, and an expiry countdown. Focus starts on Deny; Escape denies; Tab is trapped; auto-repeated keys are ignored. For a Sensitive action, a keyboard activation of Approve counts only after the user moved focus there (Tab or pointer). An expired approval is never sent.

- `crates/loki-runtime/src/stream.rs`: `ApprovalBroker` stores the pending arguments and expiry. `respond(id, approved, shown_arguments)` delivers a "yes" only if it is unexpired and `same_json` matches. Otherwise the waiting tool call gets a refusal. Four unit tests.

## Acceptance criteria
- [x] Approving binds to the shown arguments:
  - Rust: `approving_is_bound_to_the_shown_arguments` (changed value, missing or extra key, longer array, null), `a_large_integer_rounded_by_the_webview_does_not_match`, and `mock_approval_for_different_shown_arguments_runs_nothing` (end to end: nothing launched, tool Cancelled).
  - UI: "Approve sends back exactly the shown arguments for that approval, and the tool runs".
- [x] An expired approval is refused:
  - Rust: `an_expired_approval_is_refused_but_a_no_is_always_accepted` (at the expiry instant).
  - UI: "an approval left until it expires is refused", "an expired dialog disables both answers", and "approving at the expiry instant sends nothing".
- [x] Shows the tool, plain-language risk, every argument and the countdown: first ChatView test.
- [x] Default focus on Deny; Enter doesn't approve a Sensitive action without explicit focus: "Enter right after the dialog opens denies" and "Sensitive: Enter doesn't approve unless the user moved focus to Approve".

## Known limitations
- At expiry the runtime cancels the request and the dialog closes at the same moment. The chat then shows `app.open: cancelled (the user did not approve this action)`; the detail text doesn't distinguish expiry from a denial (it comes from loki-agent).
- A float argument matches the same integer (`1.0` = `1`), because JavaScript prints them identically. Large integers must match exactly, so a value the webview rounded is refused.
- The dialog sits inline in the chat column, not as a native window; `aria-modal` + focus trap only.
- Only one pending approval at a time is shown (the agent asks for them one by one).

## Security implications
- IPC surface: `respond_approval` gains a `shown_arguments` JSON parameter. It only narrows what a "yes" can do; a "no" is unchanged. No new commands or capabilities, no new network access or stored data.
- The store's single-use, unexpired, same-hash check (SEC-05) still runs after a broker "yes"; this adds a UI-binding check in front of it.
