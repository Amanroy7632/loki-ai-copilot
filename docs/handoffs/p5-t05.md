## Acceptance criteria
- [x] Revoking a grant immediately denies the next call: `mock_revoking_a_grant_immediately_denies_the_next_call`. Same runtime, no restart: time.now Succeeded, then `revoke`, then Denied. UI side: "Allow grants the capability, and Revoke takes it back at once".
- [x] Each capability's status and reason, grant and revoke: "lists every capability with its status, and the reason when it isn't available".
- [x] Unsupported capabilities shown as unavailable with the reason; Allow disabled, and the runtime refuses anyway: `permissions_report_unsupported_capabilities_with_a_reason_and_refuse_granting_them`.
- [x] Allowed-roots picker with the native folder dialog: `add_root` command plus "adds a folder through the native picker…" and "a cancelled picker adds nothing". The real dialog has **not** been clicked through by the agent.

## Known limitations
- Adding or removing a root takes the runtime write lock, so it waits until a running chat turn ends.
- A cancelled picker also clears the typed name.
- PermissionRequired / Denied capabilities can still be granted (the tool then fails with the OS reason); only Unavailable is refused, as before.
- The file-ID index resets when the tool host is rebuilt, so file IDs from earlier turns stop resolving (fails closed).

## Security implications
- New IPC surface: 6 commands. `add_root` takes only an ID; the path comes from the OS dialog, never from the page.
- New plugin: tauri-plugin-dialog, registered for Rust use only. Its JS commands are denied (no capability grants them). The fs plugin crate is linked but not registered.
- Fixed a grant-widening bug: a removed root's `file_read` grant used to remain and would apply to a new folder added under the same ID. Removing or repointing now revokes it.
- Fixed a UI bug where focus could land on a destructive button after it was clicked.
