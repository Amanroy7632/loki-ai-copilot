## Known limitations
- Retention runs at startup/save, not on a background timer. The screen states that schedule.
- Export assembles history in memory, then writes the snapshot. Large histories may need streamed
  export later. Exports are unencrypted, use a new filename, and remain after history is cleared.
- Audit records, permissions, migration backups, user exports and OS/filesystem backups remain.
  Clearing is not a forensic-erasure guarantee for storage hardware or external snapshots.
- A post-write/post-delete cleanup failure is still shown as an error, but carries
  `state_changed: true` so the UI refreshes chat/provider state. A busy/validation failure does not
  discard an ongoing conversation. Retention errors after config save leave the saved policy active.
- Mutations refuse while any runtime reader is active, including a reply or health query. Stop
  the reply and retry. Root changes still have their prior P5-T05 locking behavior.
- Model selection accepts a local tag; it does not install/download it. Health reports a missing
  model/server. Restarting with `LOKI_PROVIDER` again explicitly overrides the saved provider.

## Security implications
- Five ACL-scoped commands; no new network permissions or dependencies, no filesystem/dialog
  access granted to JS. Export paths and bytes never come from the webview. Existing files cannot
  be replaced, including via a selected symlink. Delete/retention require visible confirmation.
- Config changes rebuild policy/provider before the next turn. Exclusive mutation prevents an
  active turn from recreating deleted data; immediate busy refusal avoids queuing a writer that
  would block Stop/approval readers. Existing security suite passes unchanged.
